## 개요

- **무엇:** 패턴(입력 그림)과 필터(기준 그림)를 같은 위치끼리 곱해 모두 더하는 **MAC(Multiply-Accumulate, 곱하고 누적해서 더하기) 연산**으로 유사도 점수를 내고, 점수가 큰 쪽으로 판정하는 콘솔 프로그램.
- **왜:** AI 칩 NPU(Neural Processing Unit, 신경망 처리 장치)가 수천 개씩 동시에 처리하는 연산이 바로 MAC 이다. 이 원리를 반복문으로 직접 만들어 보고, 크기가 커질 때 연산량이 어떻게 늘어나는지 잰다.
- **어떻게:** Python 표준 라이브러리(`json`, `time`)만 쓴다. NumPy 같은 외부 라이브러리는 쓰지 않는다(과제 조건).

## 구현 요약

### MAC 연산 — `calc.py` 의 `mac()`

두 n×n 격자를 이중 `for` 문으로 돌며 같은 위치끼리 곱해 `total` 에 더한다. 크기 n 은 `len(pattern)` 으로 스스로 세므로 3×3 부터 25×25 까지 같은 코드로 처리한다.

```python
def mac(pattern, filt):
    total = 0.0
    n = len(pattern)
    for i in range (n):
      for j in range (n):
        total += pattern[i][j] * filt[i][j]
    return total
```

### 라벨 정규화 — `calc.py` 의 `LABELS` · `normalize()`

`data.json` 은 같은 뜻을 두 가지로 적는다 — 필터 키는 `cross` / `x`, 정답(expected)은 `+` / `x`. 비교하기 전에 한 규격으로 맞춘다.

| 원래 값 | 어디서 | 표준 라벨 |
|---|---|---|
| `'+'` | expected | `Cross` |
| `'cross'` | 필터 키 | `Cross` |
| `'x'` | expected · 필터 키 | `X` |

- `str(label).strip().lower()` 로 공백 · 대소문자를 정리한 뒤 `LABELS.get()` 으로 찾는다. 모르는 라벨은 `None` 이 되어 그 케이스가 FAIL 로 처리된다.
- 필터 키는 `mode_json()` 이 필터를 불러올 때, expected 는 `check_case()` 가 비교하기 직전에 정규화한다.

### 동점 처리 정책(epsilon) — `calc.py` 의 `judge()`

```python
EPS = 1e-9
if abs(score_a - score_b) < EPS:   # 차이가 1e-9 보다 작으면 동점
    return tie
```

`==` 로 비교하지 않는다. 부동소수점은 `0.1 + 0.2 == 0.3` 이 `False` 일 만큼 작은 오차를 품고 있어서, 사실상 같은 점수를 "다르다"고 보기 때문이다. 동점이면 모드 1 은 `판정 불가`, 모드 2 는 `UNDECIDED`.

### 케이스 판정 — `main.py` 의 `check_case()`

```
"size_13_2" → N = 13 → filters["size_13"] 선택 (없으면 FAIL)
           → 패턴 · Cross 필터 · X 필터가 모두 13줄인지 검사 (아니면 FAIL)
           → mac() 으로 두 점수 → judge() 로 판정 → normalize(expected) 와 비교
           → (PASS 여부, 실패 사유) 를 돌려줌. 어떤 오류도 try 로 잡아 FAIL 로
```

### 성능 측정 — `calc.py` 의 `avg_ms()` · `print_benchmark()`

- `time.perf_counter()` 로 **`mac()` 호출 구간만** 잰다. 입력 · 출력 · 파일 읽기는 측정 밖이다.
- `mac()` 을 10회 돌린 시간을 10 으로 나눠 평균을 ms 로 낸다.
- 성능 표는 크기마다 `1.0` 으로 채운 n×n 격자로 잰다(곱하는 값은 연산 횟수와 무관). `data.json` 에 없는 3×3 도 같은 방법으로 포함한다.

## 데이터 — data.json

위치: `code/data.json`

```
{
  "meta":     { "version": "1.0", "type": "json" },
  "filters":  { "size_5":  { "cross": [[…5×5…]],   "x": [[…5×5…]] },
                "size_13": { "cross": [[…13×13…]], "x": [[…13×13…]] },
                "size_25": { "cross": [[…25×25…]], "x": [[…25×25…]] } },
  "patterns": { "size_5_1": { "input": [[…5×5…]], "expected": "x" },
                "size_5_2": { "input": [[…5×5…]], "expected": "+" },
                … size_13_1 · size_13_2 · size_25_1 · size_25_2 }
}
```

| 규칙 | 뜻 |
|---|---|
| 필터 키 `size_{N}` | N×N 필터 한 쌍(`cross`, `x`) |
| 패턴 키 `size_{N}_{idx}` | 가운데 숫자 N 이 쓸 필터의 크기 |
| `expected` | 정답 라벨. `+` 는 Cross, `x` 는 X |
| `meta` | 과제 설명에 없는 항목. 판정에는 쓰지 않는다 |

패턴 값은 `0.0` / `1.0`, 필터 값은 `0.0` · `0.1` · `0.3` · `0.9` · `1.0` · `4.9` · `7.5` 가 쓰인다 (2026-11-16 확인).

## 결과 리포트

### 실패 원인 분석

**결과: 6개 중 통과 3개, 실패 3개 (2026-11-16 실행).** 실패 3개는 모두 `UNDECIDED`(동점) 판정이다.

| 케이스 | Cross 점수 (float) | X 점수 (float) | 차이 | 소수 그대로 계산한 정확값 | `>` 로만 비교했다면 | expected |
|---|---|---|---|---|---|---|
| size_5_1 | 0.9 | 0.8999999999999999 | 1.1e-16 | 0.90 = 0.90 | Cross | X |
| size_13_2 | 7.499999999999997 | 7.5 | 2.7e-15 | 7.50 = 7.50 | X | Cross |
| size_25_1 | 4.9 | 4.899999999999999 | 1.8e-15 | 4.90 = 4.90 | Cross | X |

정확값은 `data.json` 의 숫자를 Python `Decimal`(10진수 그대로 계산)로 읽어 같은 MAC 을 다시 계산한 값이다.

원인을 세 갈래로 나눠 진단했다.

| 갈래 | 판정 | 근거 |
|---|---|---|
| 데이터 / 스키마 문제 | **아님** | 키 규칙(`size_N_idx`), 크기(모두 N×N), 라벨(`+` · `x` · `cross`) 모두 정상. 정규화를 하지 않으면 실제로 6개 **전부** FAIL 이 났다 — expected `'+'` 와 판정 `'Cross'` 가 달라서, 필터 키 `'cross'` 로는 `pair['Cross']` 를 못 찾아서. 정규화로 이 갈래의 실패를 0 으로 만들었다 |
| 로직 문제 | **아님** | 10진수로 정확히 계산해도 두 점수가 **똑같다**(0.90 = 0.90 등). 판정 로직은 같은 점수를 같다고 보고 있을 뿐이다 |
| 수치 비교 문제 | **원인** | `0.1` · `0.9` 같은 소수는 2진수 float 로 정확히 담기지 않아, 곱하고 더하는 동안 1e-16 ~ 1e-15 수준의 오차가 쌓인다. 그래서 수학적으로 같은 점수가 `0.9` 와 `0.8999999999999999` 로 갈린다 |

- **epsilon 정책이 없었다면?** `>` 로만 비교하면 세 케이스 모두 **오차 방향에 따라 승자가 정해진다**(위 표의 Cross · X · Cross). 이 승자는 expected 와도 정반대라 여전히 FAIL 이고, 더 나쁜 점은 근거 없는 판정을 자신 있게 내놓는다는 것이다.
- **epsilon 정책으로는:** 차이가 1e-9 보다 훨씬 작으므로 동점으로 보고 `UNDECIDED` 를 낸다. 수학적으로 맞는 판정이다.
- **그래서 이 3건은 고칠 버그가 아니다.** 두 필터 점수가 정확히 같아 점수 비교만으로는 expected(X 또는 Cross)에 닿을 수 없는 케이스이고, 과제 규칙("동점은 UNDECIDED, 판정이 expected 와 같아야 PASS")에 따라 FAIL 이 맞다. 과제 예시의 `FAIL (동점 규칙)` 과 같은 경우다.
- 코드 실수가 FAIL 로 숨는 경우도 있었다. 개발 중 `"UNDECIDED"` 의 따옴표를 빠뜨리자 정상 데이터까지 `데이터 오류: name 'UNDECIDED' is not defined` 로 FAIL 이 났다. `try` 는 프로그램을 지켜 주지만 로직 실수도 "데이터 오류"라는 이름으로 덮을 수 있어서, FAIL 사유 뒤의 원래 오류 문구까지 읽어 갈래를 나눴다.

### 시간 복잡도 분석

`mac()` 은 n×n 격자의 칸마다 곱셈 1번과 덧셈 1번을 한다. 칸은 n × n = **N² 개**이므로 연산 횟수는 N² 에 비례하고, 시간 복잡도는 **O(N²)** 이다. 크기가 2배가 되면 칸은 4배, 시간도 약 4배가 된다.

**측정 1 — 프로그램 출력 그대로 (10회 평균, 같은 날 세 번 실행)**

| 크기 | 연산 횟수 (N²) | 평균 시간 (ms) |
|---|---|---|
| 3×3 | 9 | 0.0009 ~ 0.0011 |
| 5×5 | 25 | 0.0014 ~ 0.0017 |
| 13×13 | 169 | 0.0072 ~ 0.0099 |
| 25×25 | 625 | 0.0238 ~ 0.0273 |

**측정 2 — 흔들림을 줄여 다시 잼 (1000회 평균, 세 번 중 가장 빠른 값)**

| 크기 | 연산 횟수 (N²) | 평균 시간 (ms) | 칸 하나당 시간 (ns) |
|---|---|---|---|
| 3×3 | 9 | 0.00055 | 60.9 |
| 5×5 | 25 | 0.00142 | 56.8 |
| 13×13 | 169 | 0.00715 | 42.3 |
| 25×25 | 625 | 0.02741 | 43.9 |
| 50×50 | 2,500 | 0.10690 | 42.8 |
| 100×100 | 10,000 | 0.41954 | 42.0 |

측정: 2026-11-16, Windows 11 / Intel CPU, Python 3.14.6. `calc.avg_ms()` 를 반복 횟수만 바꿔 불렀다. 50×50 · 100×100 은 경향을 보려고 따로 잰 값이고 프로그램 출력에는 없다.

- **칸 하나당 시간이 13×13 부터 약 42 ns 로 일정하다.** 시간 = (칸 수) × (칸 하나당 시간) 이고 뒤의 값이 일정하니, 시간은 칸 수 N² 에 비례한다. 이것이 O(N²) 의 실측 근거다.
- 50×50 → 100×100 은 크기 2배, 칸 4배(2,500 → 10,000)이고, 시간은 0.10690 → 0.41954 ms 로 **3.9배** 늘었다.
- 13×13 → 25×25 는 칸 3.7배(169 → 625), 시간 3.8배(0.00715 → 0.02741 ms).
- 3×3 · 5×5 는 칸 하나당 시간이 더 크다. 계산 자체보다 함수를 부르고 반복을 준비하는 **고정 비용**이 상대적으로 크기 때문이다. 작은 크기에서는 비율이 N² 에 딱 맞지 않고, 10회 평균은 실행마다 흔들린다.
- 이 경향이 NPU 가 필요한 이유이기도 하다. 수백×수백 필터를 수천 개 쓰는 실제 AI 모델에서는 칸 수가 폭발적으로 늘어나고, 칸 하나씩 차례로 처리하는 방식(이 프로그램처럼)으로는 감당하기 어렵다.

## 설계 결정

| 결정 | 이유 |
|---|---|
| 파일 3개(`main` · `calc` · `loader`)로 나눔 | 한 파일이 길어져서. 부품(계산 · 입력)과 조립(모드)을 갈라 읽기 쉽게 |
| `==` 대신 `abs(a - b) < 1e-9` | 부동소수점 오차를 승패로 착각하지 않도록 (과제 권장 기준) |
| 같은 `judge()` 를 두 모드가 공유 | 이름만 인자로 바꿔 `A`/`B`/`판정 불가` 와 `Cross`/`X`/`UNDECIDED` 를 모두 낸다 |
| `check_case()` 전체를 `try` 로 감쌈 | 한 케이스가 깨져도 나머지는 계속 채점하고, 사유를 결과 요약에 남기도록 |
| Cross · X 필터 **둘 다** 크기 검사 | 처음엔 Cross 만 검사했다. X 필터만 크면 `mac()` 이 오류 없이 남는 칸을 무시해 틀린 데이터가 그냥 지나가는 것을 시험으로 확인하고 추가했다 |
| 크기 불일치 문구에 실제 크기를 모두 표시 | `크기 불일치: N=5, 패턴 1, Cross 5, X 5` 처럼 어느 쪽이 틀렸는지 바로 보이도록 |
| `dict.get()` 으로 찾기 | 없는 필터 · 라벨에서 `KeyError` 로 멈추지 않고 `None` → FAIL 로 처리하도록 |
| 시간을 소수 넷째 자리까지 | 셋째 자리에서는 3×3 이 `0.001` 로 뭉개져 크기별 차이가 보이지 않았다 |

## 한계 · 준비 중

- **`code` 폴더 안에서 실행해야 한다.** `data.json` 을 현재 폴더 기준으로 찾는다.
- **크기 검사는 줄 수(세로)만 본다.** 줄 수는 맞는데 어느 한 줄의 칸 수만 다른 경우는 `mac()` 에서 오류가 나고, `try` 가 받아 `데이터 오류` 로 FAIL 처리한다(멈추지는 않는다).
- **연산 시간은 기기 · 그때 상황에 따라 달라진다.** 위 표는 한 노트북에서 잰 값이다.
- **보너스 과제는 하지 않았다.** 2차원 → 1차원 배열 최적화와 패턴 생성기는 준비 중이다.
- Python 3.8 에서는 직접 돌려 보지 않았다. 3.9 이후에만 있는 문법은 쓰지 않았다.
